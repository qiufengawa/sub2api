# Frontend Refactor Exceptions

This register documents intentional exceptions to the shared-control and icon
rules. Each exception preserves a browser or product contract and must be
revisited during the final R9 audit.

| Area | File / control | Reason | Verification | Removal condition |
| --- | --- | --- | --- | --- |
| File input | `frontend/src/components/common/ImageUpload.vue`, `ProfileAvatarCard.vue`, account/settings uploaders | Native file inputs are required for browser file selection, drag/drop, MIME/size validation, and `FileReader`/canvas processing. The visible trigger uses shared buttons where possible. | File type/size rejection, preview, clear, and upload tests. | `UiFileUpload` supports the same ref/change/drop and sanitization contract. |
| Brand artwork | `PlatformIcon.vue`, `ModelIcon.vue`, `ProviderIcon.vue`, `GrokFreeIcon.vue` | Provider/model marks are data assets, not generic interface icons; replacing them with Lucide would remove brand identity. | Provider/model rendering tests and visual review. | A single approved brand asset registry replaces duplicated paths. |
| Data visualization | Chart.js canvas and `UiProgressRing`/`UiSparkline` SVG | These are data-rendering primitives, not decorative interface SVG. | Chart rendering, dark-token colors, keyboard summaries, reduced-motion checks. | Shared chart primitives expose accessible summaries and motion controls. |
| Announcement list trigger | `AnnouncementBell.vue` announcement rows | Each row is a compound two-column trigger whose copy and chevron must remain direct grid children; the shared `UiButton` slot wrapper previously nested them and caused overlap. | Announcement list interaction and keyboard button semantics. | A shared button API supports an unwrapped compound layout slot. |
| OTP/file workflows | `TotpLoginModal.vue`, `TotpStepUpDialog.vue`, `TotpSetupModal.vue`, TOTP disable, and credential upload fields | These controls use browser-specific password-manager autofill, focus, paste, ref, or file semantics. | Existing OTP timer, paste, submit, autofill, and upload tests. | Shared primitives expose equivalent ref/paste/focus/autofill contracts. |
| Ops health card | `OpsDashboardHeader.vue` health trigger | The card is a large semantic popover trigger whose layout is controlled by page-local grid CSS; it now uses `UiButton` while retaining the custom layout class. | Click, Enter/Space, popover Esc/focus restoration, fullscreen and responsive tests. | None currently; remove page-local layout only after the health card gets a dedicated compound primitive. |
| Account type/card choices | `CreateAccountModal.vue`, `EditAccountModal.vue` provider/account-type cards | These are rich, provider-specific choice cards with brand artwork, descriptions, and OAuth state transitions; replacing them with a generic segmented control would remove required metadata and change the state-machine layout. The top-level platform selector already uses `UiSegmentedControl`. | Existing account modal/OAuth/Grok/Vertex tests plus keyboard button semantics. | A shared choice-card primitive supports provider icon, description, disabled state, and selected styling without losing payload behavior. |
| Settings choice controls | `SettingsView.vue` provider-specific fields that remain in rich state blocks | Settings tabs now use `UiTabs`, and CAPTCHA/provider regions, agreement mode, Channel Monitor mode, and payment-type choices now use shared `UiButton`/segmented contracts while retaining `aria-pressed` and provider-specific values. Any future rich choice must keep its metadata and keyboard semantics. | Settings behavior suite, explicit pressed/selected attributes, and `UiTabs` keyboard tests. | A shared segmented/tab primitive supports any remaining custom content without page-local state controls. |
| Rich model/group selectors | `ModelWhitelistSelector.vue`, `GroupCopyAccountsPicker.vue` option surfaces | The selector trigger and model options carry provider artwork, check state, copy actions, and custom popover layout; only the selected-item removal action uses `UiIconButton`. | Existing model restriction and group-copy tests, keyboard/focus checks, and accessible labels on copy/remove actions. | A shared choice-card primitive supports custom option content and copy affordances without changing model IDs. |
| Rich media preview trigger | `AccountTestModal.vue` and `PlaygroundMessage.vue` generated image previews | Each native button is the entire generated-image surface with an image, MIME overlay, accessible label, and modal preview behavior; generic button padding/slot wrappers would distort media sizing. | Image-generation and preview checks, keyboard button semantics, and alt/aria labels. | A shared image-preview primitive preserves the full-bleed media surface and focus behavior. |
| Tokenized settings fields | `SettingsView.vue` remaining delimiter-aware tag fields | Registration suffixes and forwarded-client-IP headers now use `UiTextField` with shared `keydown`/`paste` event forwarding while retaining delimiter-aware commit, Backspace deletion, blur commit, and batch parsing. The exception remains only as a behavior note until a dedicated tag primitive exists. | Settings payload tests, `UiTextField` event tests, and focused manual keyboard/paste checks. | A shared tag input exposes the same commit, normalization, and accessible labeling hooks. |
| Disclosure trigger | `frontend/src/components/payment/PaymentProviderDialog.vue` per-type limits disclosure | The limits header is a semantic disclosure button with a heading, expanded state, and `aria-controls`; replacing it mechanically with a compact command button would lose the heading/chevron layout. Its body fields already use shared controls. | PaymentProviderDialog behavior tests and `aria-expanded`/`aria-controls` assertions. | Add a controlled `UiAccordion` API that supports dynamic field slots and programmatic open state. |
| Semantic disclosure trigger | `ScheduledTestsPanel.vue` plan results, `ChannelStatusV2View.vue` errors, and `ModelDistributionChart.vue` table details | These buttons expand dense result/error/chart regions and must retain row-specific content, `aria-expanded`, and `aria-controls`; a generic button wrapper would change the table/accordion layout. | Existing expansion tests plus `aria-controls`/controlled-target assertions; keyboard Enter/Space behavior remains on the native semantic trigger. | Add a shared controlled disclosure primitive with row-content slots and stable relationship IDs. |
| Semantic listbox option | `frontend/src/views/admin/settings/OpenAIFastPolicyUserSelector.vue` search result option | Search results are `role=option` buttons inside a listbox and need their custom user summary/action layout; the shared select primitives do not yet expose this result slot. | Selector tests assert listbox role, option role, `aria-selected`, selection emit, and removal. | Add a shared async listbox option primitive with custom result slots and active-descendant keyboard support. |
| Application shell geometry | `frontend/src/components/layout/AppLayout.vue`, `AppSidebar.vue` margin/width transitions | Sidebar collapse and mobile reveal animate the shell geometry itself so the active workspace does not jump; these are structural transitions, not decorative component motion. Reduced-motion rules already disable them. | App shell layout contract, sidebar collapse/mobile behavior, and reduced-motion source checks. | Replace with a shared shell layout primitive that can animate geometry without page-local transitions. |
| Rich table/media controls | `BatchImageGuideView.vue` row/thumbnail actions, `KeysView.vue` group/CCS pickers, `PaymentView.vue` help-image preview, `UseKeyModal.vue` tabs/radios/copy, `PaymentMethodSelector.vue` option cards | These controls are full row/card surfaces or native file/media/choice semantics; generic `UiButton` wrappers would add padding/slot wrappers and change selection, preview, or tab geometry. | Existing page behavior tests, explicit role/aria-expanded/aria-selected/aria-label contracts, and keyboard interaction checks. | Add dedicated shared row-trigger, choice-card, and image-preview primitives with slot-preserving geometry. |
| Application shell menus | `AppHeader.vue` account/balance triggers and menu actions; `AppSidebar.vue` group disclosure trigger | These controls own compound menu/nav content and explicit menu/disclosure roles; generic button slot wrappers would change compact header and nested navigation geometry. | AppHeader escape/focus/logout tests and AppSidebar group/mobile/runtime tests. | Shared menu and navigation disclosure primitives support compound trigger content and active routing. |
| Subscription summary trigger | `SubscriptionProgressMini.vue` active-subscription summary | The compact header trigger needs icon and two-line summary as direct flex children; the shared `UiButton` slot wrapper forced the icon/summary into an inline span and could stack the icon vertically. | Subscription summary interaction and header layout tests. | A shared button API supports an unwrapped compound layout slot. |
| Homepage hero motion | `frontend/src/views/HomeView.vue` homepage-specific hero and earth animation reduced-motion block | The public homepage owns hero entrance, hover, and canvas motion that is not emitted by shared controls; the scoped reduced-motion block explicitly freezes those named visual elements and scroll behavior. | Home three-viewport browser evidence, `HomeEarthAnimation` reduced-motion test, and homepage motion source review. | Move hero animation into a shared public-page motion primitive with equivalent named-element controls. |
| External SDK host | `AliyunCaptchaWidget.vue` native button | Aliyun CAPTCHA binds its SDK to a stable native button ID and reads the configured selector directly; replacing the host node changes the third-party lifecycle contract. | Aliyun widget SDK init/dispose and captcha action tests. | The SDK supports a framework-owned trigger adapter without requiring a native host ID. |
| Driver onboarding popover | `styles/onboarding.css`, `useOnboardingTour.ts` generated `.driver-*` nodes and scoped `tour-*` descendants | Driver.js owns the popover DOM and injects it outside Vue's component tree. The stylesheet is rooted at `.driver-popover.theme-tour-popover`, keeps custom descendants namespaced, uses UI visual/motion tokens where available, and the interactive hint renders the shared Lucide `Icon` component into the generated description node. | Onboarding tour interaction tests, static selector-scope/token checks, reduced-motion checks, and production build; verify the generated popover at the next authenticated browser acceptance pass. | Replace the third-party popover theme with a Vue-owned overlay primitive that preserves Driver.js lifecycle and positioning. |
| Auto-resizing editor | `PlaygroundComposer.vue` native textarea | The composer owns auto-resize, Enter/Shift+Enter submission, IME, paste and image/text mode focus semantics not exposed by `UiTextArea`. | Playground composer key, resize, mode and submit tests. | `UiTextArea` adds autosize and event forwarding without wrapping/height regressions. |
| Compound monitor card | `MonitorCard.vue` root button | The whole compact monitor card is a single keyboard-activatable detail trigger with status, schedule and timestamp content; generic button content wrappers would alter its grid geometry. | Monitor card click/keyboard/accessible-name tests. | Add a shared compound card-trigger primitive with slot-preserving layout. |

Exceptions are not permission to add new legacy controls. New work must use the
shared UI contracts and update this table when a new browser or business
constraint is discovered.
